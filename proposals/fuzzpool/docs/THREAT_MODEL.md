# Модель угроз fuzzpool

Участники: **заказчик** (платит, даёт цель), **воркер** (даёт вычисления, ему не доверяют),
**координатор** (проверяет и платит, доверенная сторона), **оператор** (запускает координатор).

## Воркер против системы

| Атака | Защита | Где в коде | Тест |
|---|---|---|---|
| Заявить мощность или работу, которой не было | Таких полей в протоколе нет; неизвестные поля JSON → 400; платим только за измеренное координатором | `protocol`, `coordinator/http.go: decode` | `TestEndToEndHTTP`, демо (а) |
| Прислать чужие или уже известные входы | Новизна считается по общей карте покрытия; повтор не даёт рёбер | `coordinator.creditCoverageLocked` | `TestStolenOrRepeatedInputsEarnNothing` |
| Ложный краш | Повторный прогон в песочнице; не падает → штраф из залога | `Submit`, `slashLocked` | `TestFalseCrashClaimIsSlashed` |
| Нестабильный краш | Нужны два прогона с одной сигнатурой, иначе `flaky_crash` без оплаты | `replay` | — |
| Один баг продать много раз разными входами | Дедупликация по сигнатуре: тип + верхние кадры без адресов и путей | `target.Signature`, `ParseSanitizerReport` | `TestCrashPaidOncePerSignature`, `TestParseSanitizerReport` |
| Повторить перехваченный запрос | Строго растущий nonce на воркера | `authLocked` | `TestAuthenticationAndReplay` |
| Подписать от чужого имени, перенести подпись между типами запросов | Ed25519, ID = SHA-256 ключа, домен в подписи | `identity` | `TestAuthenticationAndReplay` |
| Тысячи фиктивных аккаунтов (Sybil) | Лиза только с залогом; не больше 4 живых лиз на воркера | `Lease` | `TestLeaseLifecycleAndLimits` |
| Завалить верификатор работой | ≤64 входа × ≤1 МиБ за отправку, ≤16 отправок на лизу, ≤4 лизы, таймаут на прогон, лимит CPU в bwrap | `Config` | `TestLeaseLifecycleAndLimits` |
| Вход, который атакует верификатор (эксплойт цели) | Прогон в bwrap без сети, без доступа к хосту, ФС только для чтения | `sandbox.Bwrap` | `TestBwrapIsolation` |
| Раздуть stderr цели | Сохраняется не больше 1 МиБ вывода | `target.capped` | — |
| Гонка двух воркеров за одно ребро | Новизна и выплата считаются под одной блокировкой | `Submit` | `TestConcurrentSubmissionsPayEachEdgeOnce` |

**Остаточный риск.** Воркер может заранее прогнать мощный фаззер у себя и прислать лучшее.
Это не атака: он нашёл настоящее покрытие, и заказчик получил настоящую пользу.

## Заказчик против воркеров

| Атака | Защита |
|---|---|
| Не заплатить за найденное | Бюджет уходит в эскроу при создании кампании, до начала работы |
| Объявить работу воркера «старой» | Базис заказчика фиксируется при создании кампании; всё сверх него оплачивается автоматически |
| Подменить цель после начала | sha256 сборки закреплён в лизе; воркер отказывается фаззить другую сборку |

## Оператор против всех

| Риск | Состояние |
|---|---|
| Напечатать деньги | Невозможно без нарушения инварианта: сумма всех счетов = 0, журнал проигрывается заново (`ledger.CheckInvariant`, `GET /v1/ledger/invariant`) |
| Скрытая комиссия | Комиссия задана в конфигурации, видна при создании кампании и отдельной строкой в журнале |
| Подделать журнал | **Не закрыто в прототипе.** Нужна публикация хешей журнала или внешний аудит |
| Координатор отказывается платить | **Не закрыто.** Это доверенная сторона; снижать риск через открытый код, публичные вердикты и независимые проверки |

## Воркер против воркера

Воркер запускает чужой код (цель заказчика). Движки работают в bwrap: без сети, без `$HOME`,
писать можно только во временный каталог. Без этого платформа раздаёт удалённое выполнение
кода на машины участников.
